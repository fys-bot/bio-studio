# BioFlow Studio 面试演示脚本

目标时长：6–8 分钟
推荐角色：研究员
入口：`http://127.0.0.1:3000`

## 演示前 2 分钟检查

```bash
npm run dev
```

1. 打开登录页，确认默认研究员账号可见。
2. 登录后打开“我的 -> 开发与验收手册”，确认 API、数据与 DDL 标签可用。
3. 确认文件中心能读取目录，真实计算面板能读取示例输入。
4. 不在演示时展示 `.env.local`、Token、用户密码哈希或内部对象路径。

## 1. 产品定位（30 秒）

讲法：

> BioFlow Studio 不是普通聊天机器人。它把研究问题、项目材料、证据、分析计划、人工审批、异步计算和结果血缘放进同一个可恢复任务空间。我的重点不是复刻 Biomni 的页面数量，而是让核心工作流真实跑通，并把 Agent 在等待什么、为什么这样决策展示出来。

展示：登录页生命科学视觉、角色选择和三项能力说明。登录后指出稳定项目/任务 URL。

## 2. 文件工作区与 RAG（75 秒）

1. 打开文件中心，说明列表和预览并排，仍保留文件上下文。
2. 点击 DOCX/PDF/XLSX：展示版式/正文、解析器、字符数、分块数、索引状态和 SHA-256。
3. 拖动分栏，切换全屏，说明移动端会切换为独立阅读策略。
4. 上传一个真实文件，说明后端按格式选择 pypdf、openpyxl、python-docx 或 OCR Adapter。
5. 从文件创建任务，提问文档中特有内容，打开 RAG Trace。
6. 展示 Qdrant cosine、BM25、RRF、文件/页码/工作表定位和最终参数绑定。

重点表述：原文件不存进向量库；原件保存在对象目录，Qdrant 保存向量、片段和引用 Metadata。扫描件未配置 OCR 时返回 `needs_ocr`，不伪造全文。

## 3. 真实 LLM 计划 SSE（70 秒）

1. 进入“真实计算 + SSE”亮点实例。
2. 完成四项澄清，选择“标准模式”。
3. 点击生成分析计划，立即打开“运行过程”。
4. 展示 `plan.started -> worker.started -> plan.waiting -> worker.completed -> plan.persisting -> plan.completed`。
5. 展开任一事件，指出当前步骤、进度、耗时、等待对象、模型和原始 payload。
6. 切换快速/标准/深度研究，说明真实传递 `low/medium/high reasoning effort`，不是只改前端文案。

重点表述：SSE 是服务端真实流；等待模型期间每 8 秒有心跳。Worker 不可用时有明确的 Next.js LLM Adapter 回退，401、HTML 响应或非法 JSON 会显示具体失败阶段。

## 4. 人工审批与工作流画布（60 秒）

1. 展开计划摘要、步骤、必需输入和风险。
2. 强调高成本分析不会绕过用户直接执行。
3. 审批后打开工作流画布。
4. 拖动节点、按住空白平移、缩放、适应视图、创建一条连线。
5. 保存命名版本并刷新，确认布局和 revision 恢复。
6. 切换运行过程的时间线/画布视图，说明 SSE 事件如何映射到节点状态。

## 5. PyDESeq2 真实计算（75 秒）

1. 点击“使用示例数据”：明确输入是合成练习数据，不是患者数据。
2. 在输入与计算区检查 Count、metadata、`condition/control/treated/batch/alpha`。
3. 运行后展示 `analysis.stream.connected -> queued -> running/waiting -> completed`。
4. 说明 SQLite 保存作业，独立 Python 子进程运行 PyDESeq2；页面可离开或刷新。
5. 展示 results.csv、volcano.png、report.md 和 analysis.py。
6. 如时间允许，演示取消或错误分组，确认失败原因可读且不生成假结果。

## 6. 结果、血缘与 3D（45 秒）

1. 点击火山图候选基因，展示 log2FC、FDR 和来源节点。
2. 展示 Artifact 血缘：输入 -> 处理 -> 统计 -> 证据 -> 产物。
3. 打开 3D 结构，演示旋转、缩放、残基选择和证据联动。
4. 诚实说明当前是轻量 Canvas 结构查看器，完整 Mol* 是生产替换点。

## 7. 权限与工程质量（45 秒）

1. 退出并选择“审阅者”，用研究员账号登录，展示 `ROLE_MISMATCH`。
2. 说明审阅者只读但可写审阅意见；管理员可进入权限中心新增用户、分配角色和权限。
3. 说明 Token 在 sessionStorage，通过 Authorization Header 发送；服务重启后旧 Token 失效。
4. 打开文档中心下载 API 规范、数据库 DDL 和 Worker OpenAPI。
5. 简述测试：TypeScript、Prettier、解析器单测、真实链路 Smoke、生产构建和五档浏览器回归。

## 8. 收尾（20 秒）

> 需求文档的四项关注点均有可验证证据：产品逆向、可运行前后端闭环、前端创新交互、AI 辅助与质量安全。生产边界没有隐藏：OCR 模型、真实图数据库、完整 Mol*、多租户和专用调度仍是下一阶段。

## 面试官常见追问

### 为什么不直接上 PostgreSQL 和 Docker？

面试电脑优先保证零外部运维和单命令启动，所以本地使用 JSON + SQLite + Qdrant Local + 文件对象。真实持久化和事务边界存在，生产模型也已提供 PostgreSQL DDL；简化的是部署，不是主流程的数据处理。

### 为什么不用 EventSource？

原生 EventSource 不能方便地发送 Authorization Header。项目使用 Fetch + ReadableStream 解析 SSE，既保留 Bearer 鉴权，又能处理中断、超时、事件 ID 和错误体。

### RAG 是否真实？

用户绑定真实文件时，解析、FastEmbed、Qdrant cosine、BM25 和 RRF 都真实执行；知识图谱关系和未配置 cross-encoder 会明确标记为 Adapter/降级，不包装成真实生产能力。

### 删除文件会不会留下脏数据？

用户文件删除会清理 Worker SQLite 文档记录、Qdrant points、本地原件、任务 fileIds/dataProfiles 和旧索引。示例文件及运行中作业输入返回 `409`，避免破坏演示和正在执行的计算。

### 当前最重要的已知限制是什么？

本地存储不支持生产多租户和高并发；OCR 未配置模型时不能解析扫描正文；知识图谱和完整 Mol* 未接入；只有 RNA-seq 技能绑定真实计算器；最终演示视频需要项目提交者录制。
