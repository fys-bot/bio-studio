# BioFlow Studio 面试汇报 PPT 设计方案

> 版本：2026-09-08
>
> 建议成片：32 页主 PPT + 1 段 80-100 秒无声演示视频 + 6 段可选短视频
> 建议现场讲述：8 分钟主线，预留 3 分钟问答与功能回放

## 1. 叙事定位

不要把汇报做成“我做了许多页面”。面试官应在开场 30 秒内理解：

```text
BioFlow Studio 是把生命科学研究材料转换为可审查、可干预、可恢复分析结果的智能体工作台。
```

全篇采用一条真实研究主线：**研究员希望比较处理组与对照组 RNA-seq 数据，识别候选差异基因并交付可复现结果。**

每页顶部固定一条细的双螺旋流程线，当前阶段使用荧光黄绿色标记：

```text
登录与角色 -> 材料 -> 解析与 RAG -> Agent 计划 -> 人工审批 -> 计算 -> 结果与交付
```

因此 PPT 的组织方式是“从用户问题到工程证据”，不是从技术名词到技术名词。前 1/3 说明为什么做，中间 1/3 让面试官看到主流程如何真实运行，最后 1/3 证明它为什么可信、可扩展、可交付。

## 2. 视觉系统

### 画布与色彩

- 比例：`16:9`，推荐 `1920 x 1080`；所有系统截图保持原比例，避免拉伸。
- 基底：低饱和实验室白 `#F4F7F5`，不使用大面积纯黑或紫色渐变。
- 主强调：叶绿黄 `#DFF337`，只用于当前步骤、关键结论和主动操作。
- 信息色：显微青 `#176E64` 用于数据与 RAG；结构蓝 `#4F78B9` 用于 3D；警示朱红 `#A54236` 只用于错误和边界。
- 线条：灰绿 `#D5DDD8`，图表网格和容器尽量轻，不用叠卡片。

### 字体与信息层级

- 中文：`PingFang SC` 或 `Microsoft YaHei`；英文和数字：`Manrope`；代码和接口：`DM Mono`。
- 标题 34-40pt，正文 18-22pt，注释不小于 13pt；不用负字距。
- 每页最多一个结论标题、一张主视觉、三条以内证据说明。截图上的关键区域用编号注释，不使用密集红圈。

### 动效原则

- 只让数据和状态动，不让装饰动。DNA 片段、SSE 事件、画布拖拽、火山图和 3D 旋转是可解释动效。
- PPT 内优先嵌入 MP4；导出 PDF 时为每个视频保留一张关键帧和二维码/链接占位说明。
- 动画采用 180-260ms 淡入与路径强调；不用整页飞入或持续旋转的装饰动画。

## 3. 素材与录制清单

所有截图使用同一套受控演示数据和同一账号，隐藏 Token、绝对路径和本机用户名。建议建立以下目录：

```text
docs/presentation-assets/
  screenshots/desktop/
  screenshots/tablet/
  screenshots/mobile/
  clips/
  diagrams/
```

### 必录素材

| 素材 | 时长 | 要验证的亮点 |
| --- | ---: | --- |
| `01-login-dna.mp4` | 6 秒 | DNA 斜向片段、角色选择与默认账号 |
| `02-onboarding.mp4` | 8 秒 | 首次指引定位三条亮点实例 |
| `03-rag-llm.mp4` | 14 秒 | 对话、真实模型答复、引用与 Trace |
| `04-canvas.mp4` | 12 秒 | 节点拖拽、平移、缩放、布局保存 |
| `05-sse-compute.mp4` | 15 秒 | 计划/计算事件逐步到达、当前等待对象 |
| `06-results-3d.mp4` | 12 秒 | 火山图候选基因、3D 残基联动 |
| `07-responsive.mp4` | 8 秒 | 桌面、中屏、移动端的同一任务状态 |

### 截图准则

- 桌面：`1440 x 900`；中屏：`1024 x 768`；移动端：`390 x 844`。
- 首屏、工作流、文件预览、SSE、火山图、3D、角色权限、API 手册都必须来自真实运行页面。
- 首页数据集截图使用本轮优化后的真实预览：点击 `counts.csv` 后显示同一个 `FilePreview`，而不是“仅入口说明”弹窗。
- 能力/文件中心截图只保留一级导航和内容区，证明已经移除重复二级侧栏。

## 4. 逐页分镜

| 页 | 要回答的问题 | 主视觉与证据 | 讲述结论与下一页衔接 |
| ---: | --- | --- | --- |
| 01 | 这是什么项目？ | 工作台、双螺旋流程线、项目名 | “不是聊天壳，而是一条研究任务链。”进入研究员的问题。 |
| 02 | 为什么需要它？ | 研究材料、人工决策、计算、结果之间的断裂图 | 科研分析的痛点是上下文、过程和结果脱节。 |
| 03 | 我选了什么核心场景？ | RNA-seq 处理组 vs 对照组研究任务卡 | 用一个可验收场景承载全部产品和工程能力。 |
| 04 | Biomni 给了什么启发？ | Biomni 功能地图对照，而非逐页复刻截图 | 保留任务驱动和技能市场，重点改造过程可见性。 |
| 05 | 产品取舍是什么？ | 保留/改进/延后四象限 | 有意不堆全功能，优先把主链路跑通。 |
| 06 | 用户从哪里开始？ | 登录页关键截图 + `01-login-dna.mp4` 静帧 | 身份、角色和项目上下文先于任何科研操作。 |
| 07 | 不同角色如何改变产品？ | 研究员、审阅者、管理员权限矩阵 | RBAC 不只是文案，不同角色看到不同操作边界。 |
| 08 | 新人怎样不迷路？ | `02-onboarding.mp4` 静帧 + 三条亮点实例 | 首次指引把面试演示和新人上手统一成一条路径。 |
| 09 | 系统主流程是什么？ | 全屏主流程图，从上传到交付 | 建立后续每一页的共同坐标。 |
| 10 | 研究材料如何进入系统？ | PDF、DOCX、XLSX、CSV、图片的格式路由图 | 多模态不是一个上传按钮，而是策略路由。 |
| 11 | 文件能看见什么？ | 文件中心并排预览：原文/表格、解析器、索引状态 | 文件预览同时服务研究核对与 RAG 可追溯性。 |
| 12 | 首页数据集为什么也能预览？ | 工作台左侧数据集 -> 同一 `FilePreview` 的前后对照 | 同一对象只使用一套预览能力，消除假弹窗和重复入口。 |
| 13 | RAG 为什么可信？ | 解析、清洗、分块、FastEmbed、Qdrant、BM25/cosine/RRF 图 | 检索每一步都有真实技术边界，不把“向量库”当黑箱。 |
| 14 | 研究员怎么问问题？ | `03-rag-llm.mp4` 静帧：自然对话、引用、模型名 | 对话先检索证据，再由服务端模型答复，不再拼固定模板。 |
| 15 | Agent 如何控制模型质量？ | 模式选择器：快速、标准、深度研究 -> reasoning effort 映射 | 模式是业务意图，真实传入 LLM，不是视觉开关。 |
| 16 | 生成计划时在等什么？ | SSE 时间线截图：校验、Worker、模型等待、持久化 | 用户可以看到当前步骤、等待对象、耗时和错误原因。 |
| 17 | 为什么要人工审批？ | 计划、风险、required inputs 与批准按钮 | Agent 不能越过研究设计和结果解释的人工责任。 |
| 18 | 工作流有什么前端创新？ | `04-canvas.mp4` 静帧：拖拽、连线、平移、缩放 | 画布不是装饰，它是可编辑、可恢复的任务布局。 |
| 19 | 画布状态如何持久化？ | 节点状态机与 layout revision 小图 | 前端位置、连线和业务状态分离，刷新后能恢复。 |
| 20 | 真实计算是否跑起来？ | 输入矩阵、元数据、PyDESeq2 Worker 与 SQLite 队列 | RNA-seq 技能是真实计算器，而非静态结果。 |
| 21 | 计算过程如何可见？ | `05-sse-compute.mp4` 静帧：queued -> running -> completed | 第二条 SSE 解决长任务等待的不确定感。 |
| 22 | 失败、取消和刷新后怎么办？ | 状态迁移图 + 失败提示/重试截图 | 端到端不是只演示成功，恢复策略是核心产品能力。 |
| 23 | 最终交付什么？ | results.csv、volcano.png、report.md、analysis.py 血缘图 | 每个产物能回到输入、参数、节点和运行记录。 |
| 24 | 分析结果怎样被理解？ | 火山图截图，候选基因高亮与参数摘要 | 结果展示服务于下一步决策，而不是堆图。 |
| 25 | 3D 为什么在这里？ | `06-results-3d.mp4` 静帧，残基与证据联动 | 结构视图扩展候选基因解释，但明确当前是轻量 Adapter。 |
| 26 | 技能中心怎么避免“卡片墙”？ | 能力详情、真实/Adapter 边界、删除二次确认 | 技能有契约、输入输出、执行器状态和工作区级管理。 |
| 27 | 多端为什么可信？ | `07-responsive.mp4` 四帧：桌面、中屏、移动端 | 不是缩放网页，而是侧栏、底栏、弹层和分页的不同合同。 |
| 28 | UI 如何做减法？ | 改造前后对照：移除二级侧栏、双边框、伪弹窗 | 每个模块只保留一个明确职责，减少滚动和认知负担。 |
| 29 | 系统架构如何分层？ | Browser / Next BFF / FastAPI / LLM / Qdrant / SQLite / Worker 架构图 | 前端不拿密钥，浏览器不直连模型和数据库。 |
| 30 | 接口与安全如何工程化？ | 54 个接口的 8 域目录、Bearer、Origin、RBAC、在线契约 | API 有请求、响应、状态码和 SQL 映射，不是口头描述。 |
| 31 | 技术选型为什么这样取舍？ | 选型表：Next、MUI、FastAPI、FastEmbed、Qdrant、PyDESeq2 | 面试电脑零 Docker 启动，同时保留生产迁移目标。 |
| 32 | AI 辅助开发与 Agent 软能力是什么？ | “分析 -> 约束 -> 实现 -> Review -> 验证 -> 提交”闭环图 | 关键能力是拆解、取舍、主动暴露边界、用验证修正结果。 |
| 33 | 如何验收？ | 5-8 分钟验收路径、运行命令、GitHub 地址、二维码 | 面试官可自行重复主流程，而非只看录屏。 |
| 34 | 哪些能力不应被夸大？ | 真实能力/Adapter/生产迁移三列表 | 诚实边界反而证明工程判断：OCR、完整 Mol*、多租户仍需扩展。 |
| 35 | 最终结论是什么？ | 回到完整双螺旋流程线，显示 4 项作业要求的证据 | “从产品逆向，到可运行闭环，再到可审查的生命科学智能体。” |

> 页数可以压缩到 24 页：合并 04+05、06+07、10+11、14+15、18+19、20+21、23+24、29+30、33+34。不要为了凑页数拆开一张结论。

## 5. 工程化亮点的表达方式

工程化不能只列技术栈，建议每个亮点都用“风险 -> 机制 -> 可验收证据”的三段式：

| 工程问题 | 机制 | 现场证据 |
| --- | --- | --- |
| 模型回答不可追溯 | RAG Trace、引用、模型名、来源片段 | 对话消息点击 `[1]` 打开对应 Trace |
| 长任务没有反馈 | 两条 Bearer SSE + 当前步骤/等待对象/payload | 计划流与 PyDESeq2 流视频 |
| 文件只上传不可核对 | 格式路由与同一预览组件 | 工作台数据集和文件中心打开同一文件 |
| 前端状态刷新丢失 | 服务端任务快照、对话、画布 layout revision | 拖动后刷新，布局仍在 |
| Demo 容易伪造成功 | 失败、取消、重试、状态恢复和真实 PyDESeq2 | 刻意触发输入字段错误的截图 |
| 密钥与角色混乱 | Bearer HMAC、sessionStorage、RBAC、Origin 校验 | 研究员/审阅者/管理员权限对照 |
| 页面复杂而重复 | 页面职责梳理、去除二级侧栏、局部 Loading | 资源中心前后对照和中屏截图 |

## 6. Agent 软能力页的讲法

这一页避免说“AI 帮我写了代码”，应说明可复用的方法：

1. **陌生领域建模**：先把 Biomni 转换为用户、任务、状态、证据和失败恢复，而不是直接模仿 UI。
2. **有意识的取舍**：只让 RNA-seq DESeq2 接真实执行器；其余技能明确为 Adapter，避免假能力。
3. **安全意识**：上传材料被视为不可信数据，Prompt 明确禁止执行文档中的指令；密钥只在服务端环境变量。
4. **交互拆解**：把“看结果”拆成输入、计划、运行、证据、产物五类可独立操作状态。
5. **Review 习惯**：从截图发现重复侧栏、焦点双边框、局部 Loading、弹层尺寸等问题后，形成通用组件契约而非只打补丁。
6. **验证优先**：每阶段运行 TypeScript、Prettier、构建、Smoke 与浏览器检查，中文提交保留验收记录。

## 7. 80-100 秒演示视频脚本

| 时间 | 画面操作 | 屏幕字幕 |
| ---: | --- | --- |
| 00-08 秒 | 登录页 DNA 片段，选择研究员并进入工作台 | 角色化生命科学智能体入口 |
| 08-16 秒 | 首次指引高亮三条亮点实例 | 新人从第一分钟知道可演示什么 |
| 16-28 秒 | 点击数据集 `counts.csv`，展示真实表格预览和解析状态 | 一份材料同时服务核对与检索 |
| 28-42 秒 | 输入研究问题，展示真实 LLM 答复、引用和 RAG Trace | 回答可追溯，不是模板话术 |
| 42-57 秒 | 生成计划，展开 SSE，审批，再展示画布拖拽/缩放 | 计划可见、可审、可编辑 |
| 57-72 秒 | 启动真实计算，展示 queued/running/completed | 真实 Worker 与实时进度 |
| 72-88 秒 | 火山图选择候选基因，切换 3D 结构 | 从统计结果到结构解释 |
| 88-100 秒 | 打开开发手册 API 区、响应式四帧、GitHub | 可验收、可复用、可继续扩展 |

录制时不要输入真实密钥、个人文件或医学结论。视频使用无声配乐或无配乐，现场讲述由讲稿承担。

- [ ] 每个“真实”措辞能在 README、API 或页面中找到对应证据。
- [ ] 每个 Adapter/降级能力都同时展示边界，不包装成生产能力。
- [ ] 视频中至少出现登录、文件、RAG、SSE、画布、真实计算、火山图、3D、响应式九类画面。
- [ ] 演讲者能在 5-8 分钟内走完第 06、11、14、16、18、20、23、30、33 页。
