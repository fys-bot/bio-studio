# BioFlow Studio 后续待办工作流

## 目标

把当前“可运行的演示型科研 Agent”继续收口为“可配置、可解释、可恢复、便于代码 Review 的面试 Demo”。优先保证核心演示链路完整，再补真实数据能力和工程结构，不以堆页面数量为目标。

## 当前基线（2026-09-07 需求二次审计）

- 按工程表面完成度较高，但按需求文档和资深面试官可观察结果重新评估为约 **69/100**，不再使用“92% 已完成”的表述。
- 四项核心任务中：前后端闭环基本满足，工作流前端改进基本满足；产品逆向分析和提交材料部分满足；没有任何一项可以宣称 100% 完成。
- 当前最关键的产品偏差：Biomni 的“中心”是独立 `/skills` 页面，当前实现却是 `WorkspaceModal` 弹窗；文件中心、任务切换和项目上下文也主要依赖 React 内存状态。
- 当前仓库已有：任务状态机、鉴权 API、服务端可解释 Mock Runner、SSE、失败/重试/取消、工作流画布、RAG Trace、AI 代码流、结果血缘、可交互 Canvas 3D、CSV/TSV 真实解析、粒子化加载、配置面板和质量门禁。
- 当前仍需诚实标注为 Mock/种子数据：Agent/LLM、RAG 检索、知识图谱关系、RNA-seq 计算、3D PDB/CIF 加载、技能目录和部分固定任务数据。
- 当前演示入口：`npm run dev`，默认访问 `http://127.0.0.1:3000`。
- 当前默认场景：bulk RNA-seq 差异表达分析，默认保留“设计矩阵失败 → 局部修复 → 完成”的演示路径。

## 需求二次审计结论

详细依据见 [`analysis.md`](../analysis.md)。本轮审计真实打开了 Biomni 任务页和 `/skills` 页面，确认了以下差距：

1. Biomni 的能力中心具有独立 URL、搜索、来源筛选、分类筛选、新建技能、技能卡片和 Enabled 状态；当前 BioFlow 只有三条硬编码技能的弹窗。
2. Biomni 的任务卡、项目、云盘和工具面板围绕 URL 与服务端任务身份工作；当前 BioFlow 的部分任务和页面切换只是 React 状态或 Toast。
3. Biomni 消息包含 Trace、引用、重试、复制、审查、反馈和后续问题；当前 BioFlow 主要是全局证据条和简单回复。
4. 当前“智能体运行 39 秒”、固定文件数量和部分技能/任务内容不是服务端真相，必须删除或改为服务端快照。
5. 当前 3D 是可交互轻量 Canvas 预览，不是完整分子渲染器；必须明确降级语义，并补 PDB/CIF 适配器边界。
