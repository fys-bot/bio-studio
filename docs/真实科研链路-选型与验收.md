# 真实科研链路：选型与验收

更新日期：2026-09-07。此文档是本轮实现状态；其他带历史端口、百分比或“全部完成”的记录不作为当前验收依据。

## 本轮范围

- 一级导航负责模块切换；二级侧栏只显示最近任务和模块内条目。
- 技能整卡可点击，新建技能持久化；应用技能创建独立任务，保存 ID、版本和输入输出快照。
- 文件详情显示真实表格/正文、页/段落/工作表定位、解析器、SHA-256；原文件可下载。
- 新建任务默认真实模式。旧 `task_demo_rnaseq` 明确保留为演示，不能用于证明真实计算。

## 选型依据

| 能力        | 采用方案                           | 取舍与官方资料                                                                                                                                                         |
| ----------- | ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| PDF 文本    | pypdf 6.17.0                       | 原生文本按页提取，保留页定位；不是 OCR。[pypdf](https://pypdf.readthedocs.io/en/stable/user/extract-text.html)                                                         |
| Excel       | openpyxl 3.1.5                     | XLSX 只读、禁用外部链接、保留公式字符串而不执行。[openpyxl](https://openpyxl.readthedocs.io/en/stable/)                                                                |
| DOCX        | python-docx 1.2.0                  | 按文档顺序提取标题、段落与表格；不渲染不可信 HTML。[python-docx](https://python-docx.readthedocs.io/en/latest/user/quickstart.html)                                    |
| 扫描件/图片 | pypdfium2 + 可配置 Ollama 视觉模型 | 原生文本不足时逐页路由至 OCR；未配置模型时返回 needs_ocr，不创建假索引。[Ollama vision](https://docs.ollama.com/capabilities/vision)                                   |
| Embedding   | FastEmbed 0.8.0 / ONNX             | multilingual MiniLM-L12-v2，真实 384 维 CPU 推理；不是旧的字符累加“向量”。[FastEmbed](https://github.com/qdrant/fastembed)                                             |
| 向量存储    | Qdrant Client 1.19.0               | 单进程 Local Mode 持久化，适合本地交付；同一 API 可切 Qdrant Server。没有引入用户排除的 munus。[Qdrant Local Mode](https://github.com/qdrant/qdrant-client#local-mode) |
| 混合检索    | rank-bm25 + cosine + RRF           | 在任务绑定的 fileIds 范围内检索，保留各路分数；不伪称已启用 cross-encoder                                                                                              |
| 差异表达    | PyDESeq2 0.5.4                     | Python 实现 DESeq2 方法，可用已有 Python 环境，避免要求本机安装 R；与 R DESeq2 不保证逐值相同。[PyDESeq2](https://github.com/owkin/PyDESeq2)                           |

没有直接采用“全部转图片送视觉模型”：原生 PDF 文本、Excel 数值和 DOCX 表格应优先无损提取。OCR 用于缺少文本层的页和图片，降低成本、延迟及数值识别错误。

## 架构

```text
Browser :3000
  -> Next.js BFF: HttpOnly 会话 + Origin 校验
      -> Research Service :8000: worker token，无浏览器 CORS
          -> 原文件 data/runtime/objects/<content-id>.<ext>
          -> SQLite: 解析正文/来源元数据/作业状态
          -> FastEmbed CPU -> Qdrant Local Mode
          -> BM25 + cosine -> RRF -> 真实来源 Trace
          -> SQLite queue -> 独立 PyDESeq2 子进程 -> CSV/PNG/Markdown
```

开发目录 `.next-dev`，生产验证 `.next-verification`。研究数据、模型权重和 `.venv` 均不提交 Git。

## 策略路由与边界

1. 接收：最多 10MB；随机/哈希存储路径，文件名不参与本地路径拼接。
2. 解析：PDF 最多 100 页；Office 解压后 50MB / 5000 entries；表格最多 512 列 / 100000 行；图片最多 20MP。
3. PDF 页原生文本不足 40 字符时，路由 OCR；模型配置 `BIOFLOW_OCR_MODEL`，默认 endpoint 为本机 Ollama。
4. 视觉参数：温度 0、输出上限 4096、图片长边不超过 2000px。正文作为不可信数据，不执行文档内指令。
5. 清洗：NFC、换行和空白规范；仅检查跨页重复页边文字，不删除正文重复句或统计数值。
6. 分块：结构来源内最多 600 字符、80 字符重叠；表格每 10 行一个分组并重复列标题。保留 locator、origin、offset。
7. 索引：解析完成后后台运行真实模型，成功写入 Qdrant 才标记 indexed；失败保存错误，不静默回退假向量。
8. 检索：fileIds 由任务服务端读取，避免跨任务混检；返回原文及来源，不补齐虚构 Top 20。

## 真实计算

- 输入：genes × samples 的原始非负整数 Count 矩阵；metadata 第一列为 sample ID。
- 校验：样本 ID 精确对齐、重复 ID、缺失因素、两组标签、每组至少 2 个生物重复。
- 过滤：总计数小于 10 的基因不进入拟合；低于 10 个有效基因返回错误。
- 执行：默认一 CPU，独立 Python 子进程，上限 300 秒；排队任务持久化在 SQLite。
- 取消：取消排队作业或终止运行进程；异常不产出替代统计值。
- 恢复：服务重启将中断作业标记失败，不伪装继续计算；重试创建新 job。
- 产物：results.csv、volcano.png、report.md、analysis.py；任务页面显示库版本、样本数、设计公式、padj 和 log2FC。

- 集成：技能创建/读取/绑定任务；PDF/XLSX/DOCX 上传、正文预览、原件字节一致；扫描件保持 needs_ocr。
- 集成：真实模型向量 + Qdrant + BM25/RRF，检索命中上传文档中特有词并验证来源 fileIds。
- 集成：8 个合成练习样本、150 个基因实际运行 PyDESeq2，得到 31 个 padj < 0.05 基因；CSV 150 行、PNG 文件签名验证通过。
- 集成：错误分组字段 -> failed；重新提交生成新作业；取消 -> cancelled。

## 仍未完成

- OCR 策略和请求参数已落地，但本机没有配置视觉模型，尚未完成真实 OCR 模型验收。
- DOCX 内嵌图片当前保留在原件，不做图像 OCR；复杂 PDF 跨页表格、公式版面恢复未专项验收。
- 真实跨编码器重排、LLM 工具调用与知识图谱扩展未启用；自定义技能目前是持久化配置，不执行任意代码。
- LLM 计划的服务端适配器和审批门禁已落地；2026-09-07 已使用当前服务端配置完成一次真实供应商返回验收，HTTP 200、约 98 秒返回 9 个步骤，并持久化 `provider=llm`。这证明本地链路可用，不代表供应商 SLA 或生产稳定性已经完成验证。
- 单细胞、通路和结构技能尚未绑定真实计算器；Mol\* 仍保留为后续工作。
- 生产多租户授权、配额/杀毒、专用任务调度器、对象存储、Qdrant Server 部署、HA/监控、语义召回基准评测待做。
- 本地解析有大小/结构限制，尚未做到独立容器内的强资源隔离。

## 运行

```bash
python3 -m venv .venv
.venv/bin/pip install -r services/requirements.txt
npm run dev
```

`npm run dev` 默认 3000，尝试启动本机科研服务；不会终止占用端口的其他进程。也可在单独终端运行 `npm run services`。模型首次下载需要网络，之后使用本机缓存；文档内容默认不外发。

```bash
npm test
npm run test:parsers
npm run smoke
```

`npm run smoke` 验证真实链路，不重置现有用户任务。`smoke:legacy` 仅用于旧演示并会重置演示状态，不作为真实能力验收。
