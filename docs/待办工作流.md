# BioFlow Studio 后续待办工作流

## 目标

把当前“可运行的演示型科研 Agent”继续收口为“可配置、可解释、可恢复、便于代码 Review 的面试 Demo”。优先保证核心演示链路完整，再补真实数据能力和工程结构，不以堆页面数量为目标。

## 当前基线

- 当前完成度：约 80%（按需求文档的面试作业评价口径）。
- 已完成：产品逆向分析、任务状态机、鉴权 API、服务端 Mock Runner、SSE、失败/重试/取消、工作流画布、RAG Trace、代码流、结果血缘、3D 降级预览、粒子化加载、配置面板。
- 当前演示入口：`npm run dev`，默认访问 `http://127.0.0.1:3000`。
- 当前默认场景：bulk RNA-seq 差异表达分析，默认保留“设计矩阵失败 → 局部修复 → 完成”的演示路径。

## P0 面试演示闭环

### P0-1 真实演示脚本走通

目标：保证 5～8 分钟内能稳定展示完整价值链路。

演示路径：

```text
打开粒子加载页
→ 输入科研问题
→ 查看 Agent Trace
→ 完成四步澄清
→ 生成并审批分析计划
→ 展开工作流画布
→ 启动运行
→ 看到 RAG 事件和代码流
→ 触发失败
→ 查看证据与失败原因
→ 局部重试
→ 查看火山图、代码、结果血缘和 3D Artifact
```

验收标准：

- 任何一步刷新页面后，任务状态仍能从服务端恢复。
- 失败、重试、取消三个分支都能在 30 秒内演示。
- 所有关键按钮都有明确的视觉、Toast、抽屉或状态反馈。
- 演示数据每次重置后保持确定性，不依赖外网或真实 Token。

### P0-2 多分辨率最终验收

验收尺寸：1440×900、1280×800、1024×768、768×1024、390×844。

重点检查：

- 中屏不出现内容被挤压、遮挡或空白区域。
- 右侧 Inspector 在中屏和移动端切换为抽屉。
- 弹窗可以点击空白处和 Esc 关闭。
- 画布不会遮挡对话输入框。
- 粒子加载动画在低宽度下不出现横向溢出。

## P1 Agent 能力与生命科学场景增强

### P1-1 RAG 全链路可视化升级

当前已有事件：意图识别、检索开始、检索命中、证据重排、参数绑定。

待补：

- 增加“项目文件 / 技能包 / 文献 / 知识图谱”四类来源分组。
- 增加每条证据的来源、相关度、命中字段和绑定参数。
- 增加知识图谱小型关系视图：基因、通路、文献、分析参数之间的关系。

验收标准：用户能回答“Agent 为什么选择这个分析参数，以及这个参数来自哪里”。

### P1-2 上传文件真实解析

- CSV/TSV：读取列名、样本数、缺失值和候选分组字段。
- 自动识别 `condition`、`group`、`sample` 等常见字段。
- 解析失败时展示可操作的字段映射建议。
- 文件内容只在服务端处理，前端不展示敏感原始数据。

验收标准：上传一个真实小型 metadata 文件后，澄清卡片能根据字段自动给出默认建议。

### P1-3 3D Artifact 能力升级

- 接入 Mol* 或 3Dmol.js。
- 支持 PDB/CIF 文件加载。
- 残基选择后联动证据来源、代码上下文和结果指标。
- 保留当前轻量预览作为低性能设备降级方案。

验收标准：至少完成一个蛋白结构加载、旋转、残基点击和证据联动案例。

## 每个任务的完成门槛

每完成一个任务必须同时满足：

1. 代码实现完成，并有对应变更记录。
2. `npm run typecheck` 通过。
3. `git diff --check` 通过。
4. 浏览器至少完成一次真实点击或真实流程验收。
5. 更新本文件的任务状态和 CHANGELOG。
6. 中文提交，提交信息说明本次改动的产品价值。

## 每个阶段的完整度自测门禁

阶段不能只验证本阶段新增功能。每个 P0/P1/P2/P3 阶段结束时，都必须执行一次全量回归：

- 核心用户路径：提问、澄清、生成计划、审批、运行、失败、重试、取消、刷新恢复。
- 全部可见交互：导航、任务、文件、上传、项目、布局、配置、弹窗、抽屉、画布、结果、3D、输入框和发送按钮。
- 服务端闭环：登录鉴权、任务 API、配置 API、SSE、取消、重试、持久化和错误响应。
- 视觉与设备：1440、1280、1024、768、390 五种视口，检查溢出、遮挡、白屏和弹层关闭。
- 工程质量：TypeScript、格式、构建、smoke、Git diff 和中文 CHANGELOG。

阶段验收记录必须包含：

1. 本阶段新增功能清单。
2. 全量回归功能清单。
3. 浏览器实际操作结果和发现的问题。
4. 修复后的再次验证结果。
5. 当前仍存在的已知限制。

任何一项核心回归失败，阶段状态保持“进行中”，不能直接标记完成或提交阶段结论。
